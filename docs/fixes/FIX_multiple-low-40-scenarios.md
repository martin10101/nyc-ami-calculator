# FIX: Multiple Low-40 scenario options (ladder)

**Branch:** `fix/multiple-low-40-scenarios`
**Cut from:** `feature/excel-agent-foundation` @ `b334bcd`
**Date:** 2026-06-10
**Risk:** Low — all new solver capabilities are opt-in parameters that default to off; the ladder runs after edge-scenario generation so every existing scenario is produced by byte-identical code paths.

## Client request

The client's buyers usually prefer the smallest possible 40% AMI allocation, but the program returned only **one** "LOW 40 SHARE" scenario. The client wants **3-4 low-40 options** to choose between. Constraints from the discussion:

- Options must be **structurally different** (different apartment counts at 40%, different layouts) — never near-clones $2 apart.
- Variety must come from composition, not micro-slicing the share percentage (10.01% vs 10.02% is meaningless).
- Every option must still be the **provably best rent** for its structure.
- On small buildings with few distinct layouts, options may sit closer together in rent rather than disappear; fewer than 4 only when fewer than 4 distinct layouts mathematically exist.
- 40% units should prefer the **lowest floors** (free — a 40% unit's regulated rent depends on band + bedrooms only, never the floor).
- **Nothing else changes**: all other scenarios keep their exact rules, names, counts.

## How it works

### New solver capabilities ([ami_optix/solver.py](ami_optix/solver.py))

Three optional parameters on `_solve_single_scenario`, threaded through `find_max_revenue_scenario` and (tie-break only) `find_optimal_scenarios`. All default off — existing callers are unaffected:

- **`low_band_unit_count`** — pins the exact number of units assigned to bands ≤ 40%. Pinning different counts forces structurally different rent rolls (6 large units vs 8 smaller ones).
- **`differ_from`** — list of `(canonical_assignments, min_diff_units)`; the solution must differ from each prior layout by at least N unit assignments.
- **`low_band_floor_tiebreak`** — after the rent optimum is proven, a second solve pass locks rent at that optimum and minimizes the floor-sum of ≤40% units. Free by construction; skipped when no floor data exists.

### The ladder ([app.py](app.py), after the edge-scenario block)

Runs only when a `low_40_share` base scenario exists. Walks a recipe list until **3 additional** options are accepted:

1. `('count', k_min)`, `('count', k_min+1)`, `('count', k_min+2)` — where `k_min` is a proven lower bound on "fewest units at 40%" (largest-first greedy against the 10% SF floor).
2. `('differ', 3)`, `('differ', 2)`, `('differ', 1)` — forced-different layouts, relaxing the difference threshold so small buildings still get options.

Each rung calls `find_max_revenue_scenario` with the 40% window pinned to `[floor, floor+0.5%]` (same window as `low_40_share`), `max_revenue_combo_checks=12` to keep each solve fast, and the floor tie-break on.

**Acceptance gauntlet** (every rung's candidate must pass all):
- solver status OPTIMAL
- canonically different from every existing scenario
- hard WAAMI cap (same strictness as everywhere else)
- **outcome-distinct**: band unit-counts + monthly rent must differ from every scenario already shown — this is what guarantees "no $2 clones" and means the Fix-02 de-dupe pass never collapses these options

Accepted options become `low_40_share_2`, `low_40_share_3`, `low_40_share_4` — Excel auto-displays them as "LOW 40 SHARE 2/3/4" clustered right after "LOW 40 SHARE" (alphabetical ordering of non-reserved keys, [AMI_Optix_ResultsWriter.bas:384](excel-addin/src/AMI_Optix_ResultsWriter.bas#L384)). Each carries a client-readable description line rendered by the existing tradeoffs display ([AMI_Optix_ResultsWriter.bas:2770](excel-addin/src/AMI_Optix_ResultsWriter.bas#L2770)):

> "Low-40 option: only 6 apartments at 40% AMI, rent-maximized at the minimum 40% share."

The base `low_40_share` also gets a matching line ("best rent at the minimum 40% share") and now uses the floor tie-break.

### Placement guarantees zero interference

The ladder block runs **after** edge-scenario generation and the best_rent_roll promotion, so the edge logic sees exactly the same scenario count as before this feature (`target_edge_count` accounting unchanged). It runs **before** Fix-02 de-dupe and the final hard WAAMI cap pass, so the new options get the same end-of-pipeline scrutiny as everything else.

## What this does NOT change

- `absolute_best`, `closest_to_60`, `max_40_share`, `best_3_band`, `best_2_band`, `alternative`, `client_oriented`, `max_revenue`, edge scenarios, `best_rent_roll`, `original` — all generated by untouched code paths
- The 40% window `[10%, 12.5%]`, WAAMI cap, band caps, MIH floor-walk, UAP widening — untouched
- VBA / `.xlam` — **zero changes, no client-PC refresh needed**; the Excel side already displays whatever scenario keys arrive
- The Ctrl+Z fix from `b334bcd` — untouched

## Verified

- 7 new tests in [tests/test_low40_options.py](tests/test_low40_options.py): count pinning, infeasible-count rejection, differ-from forcing ≥N changes at equal rent, floor tie-break sinking 40% units to the lowest floors, tie-break never costing rent, unconstrained rent-max preferring fewest 40% units, and an end-to-end `/api/optimize` ladder test asserting ≥2 extra outcome-distinct, cap-compliant, window-compliant options.
- Full suite: **70 passed** (63 existing + 7 new), zero regressions.
- Synthetic 20-unit probe returns three structurally distinct options:
  - LOW 40 SHARE — 7 units at 40%, 10.24% share, $41,858/mo
  - LOW 40 SHARE 2 — 6 units, 10.10% share, $41,772/mo
  - LOW 40 SHARE 3 — 8 units, 10.46% share, $41,537/mo
  - (a 4th same-rent clone was correctly rejected by the outcome gate; richer real buildings will reach 4)

## Runtime cost

Up to 6 extra `find_max_revenue_scenario` calls per optimize request, each capped at 12 combo checks with ~1s combo time limits. Observed: the synthetic 20-unit request completes in well under the existing request budget.

Server-side only. Render auto-deploys from `feature/excel-agent-foundation`; the next "Find Optimal Scenarios" click shows the new options. Nothing to install on client PCs.
